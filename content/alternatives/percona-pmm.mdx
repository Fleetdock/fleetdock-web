Percona Monitoring and Management (PMM) and Fleetdock are both free, open-source, self-hosted tools for database teams, but they do different jobs. PMM is an observability platform: detailed metrics dashboards, query analytics and advisors for MySQL, PostgreSQL, MongoDB and Valkey/Redis. Fleetdock is a control plane for MariaDB, MySQL and PostgreSQL that runs the operations: provisioning, scheduled backups, restores, moves, users and grants, and data editing, with basic monitoring and alerts.

## What is PMM?

[Percona Monitoring and Management](https://www.percona.com/software/database-tools/percona-monitoring-and-management) is Percona's open-source tool for database observability, monitoring and management. It covers MySQL (including Percona Server and MariaDB), PostgreSQL, MongoDB and Valkey/Redis, plus ProxySQL, HAProxy and cloud services such as Amazon RDS and Aurora.

PMM has two parts. **PMM Server**, built on Grafana, VictoriaMetrics, ClickHouse and PostgreSQL, stores metrics and query data. **PMM Client** (`pmm-agent` plus exporters) runs next to each database and sends data to the server. Its main features are database-specific dashboards, **Query Analytics** that ranks queries by load with examples and explain plans, **Advisors** that check security, configuration and performance, alerting through Grafana, and backup and restore for MongoDB with point-in-time recovery (MySQL backups are listed as a technical preview in the project README).

PMM Server is licensed AGPLv3 and PMM Client Apache 2.0. Percona states there is no paid edition: every feature is open source, and it sells support.

## What is Fleetdock?

Fleetdock is an Apache-2.0 dashboard and API for MariaDB, MySQL and PostgreSQL. The **Manager** serves the dashboard and API, runs a background worker and keeps its metadata in PostgreSQL. An optional **Agent** on each server connects outbound, heartbeats every 30 seconds with CPU, memory, disk and connection figures, and runs operations locally, including launching database containers. Databases the Manager can reach over the network connect without an agent. Fleetdock sends no telemetry.

## Key differences

### Monitoring depth

This is where PMM leads. It collects detailed engine metrics through exporters and keeps them in a time-series database for Grafana dashboards. Fleetdock records server CPU, memory, disk and connections from agent heartbeats (seven days by default), checks every database server every minute, and alerts by email, Slack or webhook when a server goes offline or a backup fails. Its [performance](/docs/performance) tools are a **Top queries** list per database server, Explain and Analyze plan trees, and index health that flags unused and redundant indexes.

### Operations

Fleetdock does the work PMM leaves to other tools. It provisions MariaDB, MySQL and PostgreSQL instances as containers, runs [backups](/docs/backups) for all three engines on a schedule to S3, Cloudflare R2 or S3-compatible storage with retention, [restores](/docs/restores) them after verifying a checksum, and [moves or copies](/docs/migrations) databases between servers. It manages database users and grants, and stores credentials encrypted at rest.

### Working with data

Fleetdock includes a [data browser](/docs/data-browser) with undo for every saved edit, a [SQL console](/docs/sql-console) with a rolled-back preview of write scripts, [fleet query](/docs/fleet-query) across up to 500 databases, and [schema history](/docs/schema-history) that records structural changes. PMM is built for observing databases rather than editing their contents.

### Engines

PMM covers MongoDB and Valkey/Redis; Fleetdock does not. Fleetdock backs up PostgreSQL as well as MariaDB and MySQL; PMM's backup features center on MongoDB and MySQL.

## When to choose PMM

- You need detailed, long-term performance metrics and dashboards.
- You want query analytics across a fleet, with load ranking and examples.
- You want automated advisor checks for security and configuration.
- You run MongoDB or Valkey/Redis.

## When to choose Fleetdock

- You need scheduled backups, restores and database moves for MariaDB, MySQL and PostgreSQL.
- You want a web data browser and SQL console with undo and write previews.
- You manage many databases, such as one per tenant, and want to query or change them together.
- Basic server metrics and alerts are enough for monitoring, or you already have a monitoring stack.

## Can you use them together?

Yes, and they complement each other. Run PMM for metrics, query analytics and advisors, and Fleetdock for backups, restores, user management and data work. Each connects with its own database login, so neither has to know about the other.

<Callout type="info">
  Fleetdock does not manage replication, high availability or automatic failover. Keep your
  existing replication setup for that.
</Callout>

## Getting started

Fleetdock installs on a Linux server with 2 vCPU and 4 GB of RAM using `curl -sSL https://fleetdock.dev/install.sh | sudo sh`, which sets up automatic HTTPS. Follow [Getting started](/docs/getting-started) to connect your first database server; PMM can keep monitoring the same servers.
